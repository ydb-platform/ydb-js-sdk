---
'@ydbjs/telemetry': minor
---

Drop the `pessimization.until` span-event attribute from the `ydb:driver.connection.pessimized` subscriber. The endpoints engine in `@ydbjs/core` no longer emits `until` (pessimization has no fixed timer), so the subscriber was writing `NaN` (`undefined / 1000`) as the attribute value under an active span. The `ATTR_YDB_DRIVER_CONNECTION_PESSIMIZATION_UNTIL` semconv constant is kept but deprecated.

Add the `ydb.node.pile` (`ATTR_YDB_NODE_PILE`) span-event attribute to every `ydb:driver.connection.*` mapping, so bridge (2DC) traces show which pile each node belongs to alongside `ydb.node.dc`. The attribute is omitted on a non-bridge cluster (empty pile name). Optional span-event attributes are now stripped explicitly: `span.addEvent` — unlike `span.setAttributes` — keeps undefined-valued keys, which the OTLP transformer ships as valueless attributes.

Map the remaining bridge (2DC) topology channels emitted by `@ydbjs/core`:

- **Traces.** The `ydb:driver.discovery.completed` mapping now also sets `ydb.discovery.self_location` (whenever the server reports one — it drives ordinary locality tiering too, so it is not bridge-specific) and, on a bridge cluster, `ydb.discovery.primary_pile`. A new `ydb:driver.pile.changed` mapping records a `ydb.driver.pile.changed` span event on the discovery span it fires within, carrying `ydb.driver.pile.primary_before` / `primary_after` plus the full `ydb.driver.pile.before` / `after` rosters as `name:STATUS` string arrays — the producer fires on any roster or status change, not just a primary handover, so the scalars alone would describe nothing.
- **Metrics.** New observable gauges mirror the routing snapshot from `ydb:driver.connection.pool.stats`: `ydb.driver.pool.total`, `ydb.driver.pool.routable` (tagged `ydb.routing.tier` ∈ {`prefer`, `fallback`}), `ydb.driver.pool.pessimized`, and `ydb.driver.pool.nodes` (per bridge pile, tagged `ydb.pile.name`). Pile **status** is deliberately not a dimension of the node _count_: it is mutable, and cumulative temporality never retires a series, so tagging a count by it would fork `pool.nodes` on every failover and double the sum. Status instead gets a state-set gauge `ydb.driver.pile.status` — `1` for a pile's current status and `0` for every other member of the enum, re-observed in full each collection cycle so a transition overwrites the stale pair rather than stranding it. Both gauges also observe `0` for any pile that has left the roster, so a decommissioned pile decays instead of reporting its last node count forever. Find the primary pile with `max by (ydb.pile.name) (ydb_driver_pile_status{ydb_pile_status="PRIMARY"})`. The routing mode from `ydb:driver.connection.pool.opened` rides its own info-style gauge `ydb.driver.pool.config` (always `1`, tagged `ydb.routing.prefer_primary_pile` / `ydb.routing.locality_enabled`) so it can never vary the attribute shape of `routable`. Two counters track pile transitions: `ydb.driver.pile.fallbacks` (tagged `ydb.pile.fallback.active`) and `ydb.driver.pile.changes`.

All pool state is keyed by driver identity and dropped on `ydb:driver.closed`, which stops the pipeline observing that driver — note this does not retract series an exporter has already scraped, since cumulative temporality carries the last value forward. Pool snapshots are tracked separately from the `connection.*` delta counters, so a subscriber that attached late no longer reports `ydb.driver.connection.count = 0` for a driver that has live connections.

Harden the metrics subscribers: `diagnostics_channel` invokes them synchronously on the publisher's stack and re-raises a throw as an `uncaughtException`, so a malformed payload could take down the host application. Handlers now catch and report via OTel's `DiagLogger`, matching the traces pipeline, and the batch observable callback is guarded so one bad payload cannot blank every instrument in the collection cycle.
